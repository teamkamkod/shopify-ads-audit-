What was reported

REPORTED

After installing the app, /app answered HTTP 500 Internal Server Error instead of loading the dashboard.

Root cause (measured, not assumed)

Two requests that Shopify's automated security checks send during review were answered with an unhandled exception escaping as a 500. The second one is the one that reached production:

[Request A]  GET /app?embedded=1&host=9998322874899999999&shop=cross-shop-missing-….myshopify.com
  TypeError: Invalid URL
      at new URL (node:internal/url)
      at Object.sanitizeHost (…/lib/utils/shop-validator.ts:58:26)
      at validateShopAndHostParams (…/authenticate/admin/helpers/validate-shop-and-host-params.ts:21:28)
      at Object.authenticateAdmin (…/authenticate/admin/authenticate.ts:155:9)
    code: 'ERR_INVALID_URL', input: 'https://÷ß|ßm¼ï\x8F=÷ß}÷ß'
  → HTTP 500

Shopify sends a non-base64 host value as part of its checks. The library base64-decodes it and passes the result straight to new URL() without a guard, so the exception is never turned into a response. The same class of defect existed on the webhook path (a valid-signature request with a non-JSON body), which is why those webhooks answered 500 too.

No trace was visible in production logs: NODE_ENV=production silences the library logger, so the exception left no log line at all — the 500s were correlated by hand from request timings, container start time and the routes' own log lines.

The fix

Both malformed-input paths are now caught before the library sees them, and the library is never allowed to turn an exception into a 5xx on these paths. Routes keep their existing authenticate.admin() / authenticate.webhook() call sites — only the import path changed.

app/shopify-auth.server.ts   — hardened authentication wrappers (new file)
app/routes/*                 — one import line changed per route
webhooks.app.uninstalled.tsx — session cleanup made unconditional

Resolved state — re-run the exact requests now

These requests are sent from your own browser to the live production app, so the result is the current state of the submitted app, not a screenshot.

Press "Run the checks" to send the requests that previously returned 500.

A 410 Gone in the output means the request came from an automated/headless client: the Shopify library rejects bot user-agents before it authenticates anything, by design. From a normal browser the same requests answer 400 (A and B), 302 to the install flow (C) and 200 (D) — that is what the table below records.
